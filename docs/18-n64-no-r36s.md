# 18 — N64 no R36S: Ocarina of Time

Teste real do **The Legend of Zelda: Ocarina of Time** (USA, Rev 2 — `.z64` de 32 MB) no aparelho, com medição de velocidade e ajustes aplicados. O resultado principal: **o jogo roda praticamente a 100% da velocidade**, e os 20 fps que aparecem na tela são o ritmo nativo dele, não falta de desempenho.

## O que o aparelho tem

- **Emulador:** mupen64plus **2.5.9 standalone** em `/opt/mupen64plus`, com dois plugins de vídeo: **Rice** e **Glide64mk2**. Não há core de N64 no RetroArch desta imagem (a lista de cores do menu cita `parallel_n64`/`mupen64plus_next`, mas os arquivos não estão lá).
- **Launcher:** `/usr/local/bin/n64.sh`, chamado pelo EmulationStation em `/etc/emulationstation/es_systems.cfg` com `sudo perfmax %EMULATOR% %CORE%; nice -n -19 /usr/local/bin/n64.sh %EMULATOR% %CORE% %ROM%; sudo perfnorm`.
- **Saída de vídeo:** OpenGL ES 3.2 no Mali-G31.
- **ROM:** `/mnt/jogos/n64/Legend of Zelda, The - Ocarina of Time (USA) (Rev 2).z64`, reconhecida como `THE LEGEND OF ZELDA` (V1.2, CRC `693BA2AE B7F14E9F`).

## Como medir de verdade

O contador do **Glide64mk2** mostra três números ao mesmo tempo (`show_fps = 7`): FPS desenhados, VI/s (o relógio do N64, 60 por segundo) e **% de velocidade**. É esse terceiro número que diz se o emulador está acompanhando o jogo.

O Rice tem `ShowFPS`, mas **não desenhou nada** na tela nas nossas capturas. Por isso a comparação com números foi feita no Glide.

As capturas foram tiradas com o `drmcap` (ver [08](08-captura-de-tela.md)), com o EmulationStation parado, e o FPS lido do próprio contador na imagem.

## Resultados medidos

Cena: demo automática do título (Link a cavalo em Hyrule Field), 30–50 s após abrir.

| Configuração | FPS | VI/s | Velocidade |
|---|---|---|---|
| Glide, padrão (vsync ligado) | 20,35 | 57,34 | **95%** |
| Glide, padrão (vsync desligado) | 20,72 | 58,39 | **97–98%** |
| Glide, preset leve + vsync desligado | 19,9–20,7 | 58,4–63,6 | **99–106%** |
| Rice, resolução nativa do N64 | — (sem contador) | — | — |

- **O jogo é de 20 fps por natureza.** O Ocarina of Time foi feito para rodar a 20 quadros por segundo; o contador em ~20 fps com 100% de velocidade significa que o emulador está no ritmo certo, não que esteja lento.
- **Custo de CPU:** 73–85% de **um** núcleo (o emulador é essencialmente single-thread), com os 4 núcleos disponíveis.
- **Memória:** ~144 MB de RSS no início, ~155 MB depois de 50 s.
- O Rice, na mesma cena, teve o mesmo perfil de CPU do Glide (74–85%), mas a imagem fica mais serrilhada por renderizar na resolução nativa.

## Ajustes aplicados

Configuração em `/home/ark/.config/mupen64plus/mupen64plus.cfg`:

**Glide64mk2** (emulador escolhido para o Ocarina):

```
vsync = False
show_fps = 0
wrpResolution = 0
ghq_fltr = 1
ghq_enht = 0
ghq_hirs = 0
ghq_cmpr = 0
wrpAntiAliasing = 0
```

**Rice** (alternativa, caso o jogo seja trocado para ele):

```
InN64Resolution = True
TextureEnhancement = 0
ForceTextureFilter = 0
Mipmapping = 0
AnisotropicFiltering = 0
```

Também criei `/home/ark/.cache/mupen64plus/glidehq`, que faltava: o Glide registrava dois erros ao não conseguir entrar nessa pasta.

A escolha do emulador por jogo fica no `gamelist.xml`:

```xml
<game>
  <path>./Legend of Zelda, The - Ocarina of Time (USA) (Rev 2).z64</path>
  <name>The Legend of Zelda: Ocarina of Time</name>
  <emulator>standalone-Glide64mk2</emulator>
</game>
```

## Um bug real no launcher

O `n64.sh` original usava `$2` como ROM:

```bash
/opt/mupen64plus/mupen64plus ... --datadir /opt/mupen64plus "$2"
```

Mas o EmulationStation chama `n64.sh %EMULATOR% %CORE% %ROM%`. Para emuladores standalone, o `%CORE%` vai vazio, então a **ROM caía em `$3`** e o emulador abria com ROM vazia (`couldn't open ROM file ''`).

Correção (em `/usr/local/bin/n64.sh`, backup em `n64.sh.bak`):

```bash
ROM="${3:-$2}"
```

Assim funciona nos dois formatos: standalone (`emulador rom`) e RetroArch (`emulador core rom`).

## O que fazer se quiser mexer

- Trocar o emulador de um jogo: no menu do EmulationStation, opções do jogo → emulador; ou editar o `<emulator>` no `gamelist.xml` (com o ES parado).
- Testar outro plugin: `standalone-Rice` no mesmo lugar.
- Ver o contador de FPS de novo: `show_fps = 7` no Glide e reiniciar o jogo.

Os scripts usados estão em [`experimentos/n64/`](../experimentos/n64/): `teste-n64.sh` (roda uma variante, captura a tela, mede CPU/RSS e restaura), `aplica-n64.sh` (aplica a configuração acima) e `n64.sh` (a versão corrigida do launcher).

## O que não foi medido

- Áudio: os testes foram com `SDL_AUDIODRIVER=alsa`, mas não houve como ouvir o aparelho. Se houver estalo, o caminho é aumentar o buffer do plugin de áudio.
- Sessão longa (temperatura/bateria além de ~1 min de teste).
- Outros jogos de N64 e outras áreas do Ocarina (Kakariko, Market, lutas), que podem pesar mais que a demo de Hyrule Field.
- O Rice não tem contador visível; a comparação com ele foi por CPU e por imagem, não por % de velocidade.
